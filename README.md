# 하루결 — Plan · Do · See 다이어리

월간 달력과 날짜별 일정, 주간 목표와 월~일 할 일 보드, 가계부, 독서·미디어 기록을 반응형 다이어리로 정리했습니다. 오늘 화면의 달력에는 일정만 표시하고, 달력에서 과거·오늘·미래 날짜를 선택해 기록할 수 있습니다. 계획 화면의 주간 목표는 요일별 할 일과 별도로 추가·완료·삭제할 수 있습니다. 할 일 태그는 직접 입력하거나 공부·습관·취미·운동 중 선택합니다. 회고와 기록 보관함은 유지했고 공개 범위 안내는 페이지 하단으로 옮겼습니다. 과제의 계획 수정 이력과 실행 기록, 예상/실제 시간 회고도 포함했습니다.

할 일 제목·일정·주간 목표·요일별 계획 내용에는 추가된 온글잎 박다현체를 사용합니다. 요일별 계획의 상태 박스를 누르면 준비 → 완료(✓) → 진행 중(△) → 미실행(×) 순으로 바뀝니다.

요일 카드를 누르면 해당 날짜의 할 일만 보여주는 집중 창이 열리고 배경 화면은 흐리게 표시됩니다. 집중 창에서 할 일 상태를 바꾸거나 그 날짜의 할 일을 추가할 수 있습니다.

월간 달력 일정은 추가·수정할 때 색을 선택할 수 있으며, 선택한 색이 날짜 칸의 일정 띠에 표시됩니다. 일반 글꼴은 SUIT 계열로 조금 더 부드럽게 조정하고 기본 글자 크기를 약 1px 키웠습니다. 온글잎 박다현체가 적용된 일정·목표 텍스트와 두 영문 제목은 기존 설정을 유지합니다.

가독성을 위해 글자 크기를 다시 조정했고 달력 안내·상단 문구·프레임 레이블은 줄바꿈하지 않도록 했습니다. 독서·미디어 기록에는 표지 이미지 업로드, 작가/감독, 간단한 소개, 별점, 짧은 감상을 추가했습니다. 표지 이미지는 로컬 브라우저 저장 공간을 고려해 축소 후 저장합니다.

## 열기

`run-diary.cmd`를 실행하고 `http://127.0.0.1:42831`을 여세요. Node.js 24 이상이 필요합니다. T06 기록은 기존 06 다이어리에서 JSON 데이터 내보내기를 한 뒤, 이 로그인 화면에서 백업 파일을 선택해 옮길 수 있습니다.

## 공개 주소에서 로그인과 저장 사용

Vercel은 GitHub 저장소의 화면과 `/api` 로그인 기능을 배포하고, Supabase Free는 계정과 다이어리 자료를 저장합니다. 계정 연결과 초기 DB 설정 절차는 [`VERCEL-SUPABASE-SETUP.md`](VERCEL-SUPABASE-SETUP.md)에 정리했습니다. Supabase URL과 Secret key가 Vercel 환경 변수에 설정된 뒤 공개 주소에서 로그인과 계정별 저장을 사용할 수 있습니다.

## 현재 구현 범위

- 계획 생성 및 수정 이력 보관
- 할 일 추가·수정·삭제, 완료/완료 취소, 검색, 상태 필터, 마감일·우선순위 정렬
- 완료 시 실제 시작·종료 시각 및 소요 시간 입력, 작업별 실행 기록 중복 방지
- 주간 회고의 계획·완료·지연·막힘 수, 예상/실제 시간 차이 및 근거 보기
- 가계부와 독서록을 독립 메뉴로 분리하고, 가계부에 월 지출 목표·분류별 예상 지출·사용액·잔액·예상 잔액 합계
- 계획에서 요일을 열어 할 일별 실제 시작·종료 시각과 소요 시간, 막힘 사유를 입력하고 회고에 반영
- 회고 개선점, 가계부, 독서·미디어 기록
- 회고 화면의 5일 실사용 기록: 첫날 질문·지표·단위·계산 방식·초기 규칙 설정, 둘째 기록 이후 셋째 기록 전 규칙 변경 시각과 이유 저장, 변경 전후 합계·평균의 산식 표시
- JSON 전체 내보내기와 스크립트 문자열 이스케이프 표시

5일 기록은 회고 화면에서 직접 진행합니다. 실제로 관찰한 날짜와 값만 입력하며 예시 기록은 미리 채우지 않습니다. 같은 지표·단위·계산 방식을 5일 동안 유지하고, 1·2일차 기록 후 3일차 기록 전에 규칙을 한 번 변경하세요. 화면은 변경 전 1~2일차와 변경 후 3~5일차의 합계·평균 산식을 함께 보여 주므로 직접 계산한 값과 대조할 수 있습니다. 날짜는 순서대로, 실제 기록한 날짜로 입력해야 합니다.

## 저장 및 과제 제출 상태

로컬 실행에서는 Node.js 서버와 SQLite를 사용하고, 공개 배포에서는 Vercel API와 Supabase Postgres를 사용합니다. 양쪽 모두 계정별 무작위 salt를 적용한 scrypt 해시를 보관하고 7일 뒤 만료되는 세션을 사용합니다. 실제 DB 파일은 `.gitignore`와 `.vercelignore`로 저장소 및 배포 파일에서 제외합니다.

비로그인 사용자는 로그인 화면만 볼 수 있습니다. 사용자 자료 API는 로그인 세션에서 확인한 계정 자료만 반환하고 갱신합니다. 가입 시 기존 JSON 백업을 선택하면 해당 계정 자료로 병합합니다. 원본 JSON은 삭제하지 않습니다.

비밀번호 salt 분리, 세션 만료·로그아웃 무효화, 양방향 계정 자료 격리(읽기·수정·삭제), 목록 응답과 비로그인 직접 요청을 다시 확인하려면 `node security-check.js`를 실행하세요. 결과는 [`SECURITY-REPORT.md`](SECURITY-REPORT.md)에 비밀번호·토큰·비밀키를 마스킹해 저장합니다. 설계 근거는 [`SECURITY.md`](SECURITY.md)를 참고하세요.

## 확인 방법

1. `run-diary.cmd`를 실행하고 `http://127.0.0.1:42831`로 이동합니다.
2. 로그인하거나 가입합니다. 아이디는 중복될 수 없고, 로그인 실패 안내는 같은 문구를 사용합니다.
3. T06에서 내보낸 JSON이 있으면 로그인 화면에서 선택합니다. 다이어리 화면이 열리면 기록을 추가하고 새로고침해 저장을 확인합니다.
4. `index.html`을 `file://`로 직접 열면 로그인은 작동하지 않습니다. 서버를 실행해 로컬 주소로 접속하세요.

## AI와 내 판단

- AI에게 맡긴 일: 이미지 기능 분석, 화면 구조와 상호작용 코드 및 데이터 계약 초안 작성.
- 내가 직접 판단한 일: 민감한 자료를 넣지 않도록 공개 범위 안내를 상단에 두고, 실행 시간은 사용자가 직접 기록하게 구성.
- AI 제안을 따르지 않은 일: 예시 계획이나 실행 기록을 넣지 않았습니다. 실제 개인 기록을 임의로 만들면 과제 목적과 맞지 않기 때문입니다.
